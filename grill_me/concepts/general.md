# Concept ledger — general software engineering

Cross-repo curriculum of transferable software-engineering concepts. Unchecked = still in retest rotation. See "The concept ledger" in SKILL.md for the rules; topic-specific ledgers (e.g. machine-learning.md) live alongside this file. (Curated 2026-07-23: nailed entries removed — TOCTOU conditional-update, removeEventListener reference identity, merged-transaction savepoints; same-family entries merged; histories compressed to introduced + latest status.)

- [ ] Idempotency keys & the dual-write problem — two systems with no atomic commit strand one side on a crash between writes; the fix family is caller-chosen idempotency keys on the remote mutation (retry returns the original result), write-ahead intent records, and reconciliation sweeps — and keys must version their inputs: ON CONFLICT DO NOTHING dedupes by key, so a changed producer leaves stale rows under old keys unless stored provenance is compared and wiped on mismatch (introduced 2026-07-07, Stripe create + local mirror; provenance variant answered well 2026-07-14)
- [ ] Stored state vs. computed state — stored derived values are indexable/searchable but drift; computed can't drift but can't be sorted/searched in SQL and makes regression an implicit deploy side effect; resolution: compute the default, store only the exception — and a stored derived value is only as fresh as the set of write paths that recompute it: every new write path (controller, job, console) silently opts out, so sync at the source or fail loud on missing context (absorbs the attribution-seams entry; introduced 2026-07-07 onboarding frontier + 2026-07-13 Statusable actor; applied well 2026-07-23, derive_name_from_person)
- [ ] Fail-open vs. fail-closed — know which way every guard fails before you need it; the right direction is conditional on what it protects (access control = closed, UX convenience = open), and fail-open's mandatory complement is loud telemetry: a fail-soft integration renders an incident identical to a quiet day, so cap spend/quota and alert at the source (introduced 2026-07-07, subscription gates; 2026-07-23 Places proxy — missed the telemetry half)
- [ ] Lease-based claims — a row lock (FOR UPDATE SKIP LOCKED) protects only the claim instant; the processing window needs a persistent lease column, every lease needs a reaper, worst-case recovery = staleness horizon + sweep period + pickup latency, and a zombie holder is indistinguishable by identity — each (re)claim needs a fencing token (attempts/epoch counter) echoed inside every conditional write (absorbs the fencing-tokens entry; introduced 2026-07-11/14, ingestion_tasks claim)
- [ ] Defensive defaults must fail loud, not plausible — pre-initializing with a normal-looking value converts a crash into silently wrong data; prefer structure that forbids the state, then a sentinel that blows up, never a plausible default; in rendering contexts: honest empty + error report, never a fake value and never a raise that 500s a whole collection view for one bad row (introduced 2026-07-11, process_task; retested shaky 2026-07-16)
- [ ] Stuck states need threshold sweeps — a lost report or dead worker raises no exception for an event monitor; stranded rows are a *state*, caught only by a periodic sweep over the DB (also the reaper's skeleton), and the sweep's own predicate has blind spots — consumer liveness needs its own signal (oldest-queued age, attempts alerts) (introduced 2026-07-11; blind spot missed 2026-07-14)
- [ ] Capacity/runtime claims are checkable — "which resource exhausts first" and "what this code does at runtime" must anchor to the actual config or the actual line, not a plausible mental model; open the file before committing to the claim (introduced 2026-07-11, RAM-vs-Puma; the recurring meta-gap — resurfaced 2026-07-23 as "sorting dominates" and unanchored GC/AASM claims)
- [ ] Transactions don't serialize read-compute-write — a bare transaction gives atomicity of your own writes, not isolation from concurrent actors; serializing overlapping recomputes needs a row lock or one conditional UPDATE; under READ COMMITTED the loser of a raced invariant write errors (first committer wins) and cross-row invariants have no constraint backstop; convergent recompute-on-event heals staleness only if a future event arrives — terminal events (win/lose) need a lock or a sweep (absorbs the idempotence-by-convergence entry; introduced 2026-07-13, refresh_outcome!; retested partial 2026-07-16)
- [ ] Untrusted input must never select code — whitelist-then-dispatch before any send/public_send; safety-by-naming-coincidence (may_*? gating) is one refactor from arbitrary bang methods, and the whitelist doubles as the authorization statement (introduced 2026-07-13, transitions EVENTS)
- [ ] AR materialization dominates read-then-aggregate paths — the cost is instantiating/typecasting thousands of wide AR objects (~10× the query: BigDecimal/Time casts + GC churn inside the request), not the SQL and not the in-memory sort; aggregate in SQL or pluck into structs, never instantiate what you'll immediately reduce; flat query-count tests can't catch it, and APM shows it as app-time between fast SQL spans (introduced 2026-07-13, EstimatorWorkload; missed again 2026-07-23, BidResults — "sorting" diagnosed)
- [ ] Expand-contract for enum value changes — RENAME VALUE is an in-place breaking change: mid-rolling-deploy, old code writing the old value 500s; safe path is add value → deploy dual-read code → backfill → retire, and PG enum values can never be dropped (introduced 2026-07-13, employee→estimator)
- [ ] Authentication is not authorization scope — a shared secret proves "is the trusted caller," not "may touch this resource"; with enumerable IDs and an unscoped credential, one leaked secret collapses the whole tenant boundary (introduced 2026-07-14, worker HMAC)
- [ ] Contract fixtures must come from the counterpart — mirrored signers/serializers tested against your own re-implementation are copies of one assumption; drift is only catchable by a golden fixture generated by the other side, or a real cross-system test (introduced 2026-07-14, triple-implemented HMAC)
- [ ] Ruby closures, def scope, and DSL-lambda evaluation — blocks/lambdas capture surrounding locals while `def` opens a sealed scope; Rails DSL blocks (scope bodies, `conditions:`, has_many lambdas) are instance_exec'd against a relation at query time, so bare method calls resolve on the rebound receiver while locals still come from the closure; an eager body evaluates once at boot (frozen timestamps, boot-time DB access) — the lambda defers to query time and composes (merges the three 2026-07-16 entries: closures vs def, instance_exec rebinding, lazy DSL lambdas)
- [ ] Direct-upload topology — metadata-first: the blob row is a write-ahead intent record before any bytes move (the `unattached` scope is the reconciliation sweep); failures move client-side with the bytes — a CORS-blocked S3 PUT is invisible to server logs, so the JS error callback must report, not just relabel (introduced 2026-07-16, dropzone)
- [ ] Retrofit asymmetry is the steel-man for YAGNI — the strong case for building early is never "we'll need it," it's "the assumption ossifies into data and N read surfaces"; YAGNI is safe exactly when the assumption is centralized in one seam — so defer, but name the paths that bypass the seam (introduced 2026-07-16, document-permission axis)
- [ ] Postgres ordering contracts: DISTINCT ON + NULL position — DISTINCT ON always returns one row per group; the ORDER BY (leading with the DISTINCT ON keys) decides *which*, and without it the row is plan-dependent: silent nondeterminism single-row fixtures can't expose; NULL sorts as larger-than-everything in PG (NULLS FIRST on DESC — convention, not three-valued logic; MySQL picks the opposite), so portable ORDER BY states NULLS LAST explicitly (introduced 2026-07-23, final_bid_join — both halves shaky)
- [ ] Listeners on long-lived targets root their closure graph — document/window outlives the component, so listener → bound fn → controller → detached DOM subtree stays reachable: the leak is what the handler transitively retains, not the handler; element-scoped listeners die with their element even if never removed; stacked handlers fail loud when their effects hit live DOM/network (N submits) and silent when they land on detached nodes (leak only) (introduced 2026-07-23, address_autocomplete onOutsideClick — retention chain handed over)
- [ ] Class-level answers to instance-level questions — AASM events own a LIST of transition objects (one per `transitions` line; current state + guards pick the winner at fire time), so `.transitions.first.to` is correct only while every event is single-destination — an unenforced invariant one added line breaks silently (a lying button label); resolve against the record's current state, or pin the invariant with a loud test (introduced 2026-07-23, stage_event_destination — missed)
